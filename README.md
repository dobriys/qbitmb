# qbitmb

Стандартный веб-интерфейс qBittorrent, который умеет показывать скорость в битах: Кбит/с и Мбит/с вместо КиБ/с и МиБ/с. Устанавливается как Docker mod для образа [linuxserver/qbittorrent](https://docs.linuxserver.io/images/docker-qbittorrent).

*Stock qBittorrent WebUI with an option to show speeds in bits (kbit/s, Mbit/s). Shipped as a linuxserver.io Docker mod.*

## Установка

1. Добавьте мод в `docker-compose.yml`:

   ```yaml
   services:
     qbittorrent:
       image: lscr.io/linuxserver/qbittorrent:latest
       environment:
         DOCKER_MODS: ghcr.io/dobriys/qbitmb-mod:latest
   ```

   Пересоздайте контейнер командой `docker compose up -d`. Мод положит интерфейс в папку `/qbitmb` внутри контейнера.

2. В qBittorrent откройте **Настройки → Веб-интерфейс**:
   - включите **«Использовать альтернативный веб-интерфейс»**;
   - в поле **«Расположение файлов»** укажите `/qbitmb`.

3. Откройте **Настройки → Поведение → Интерфейс**, включите **«Показывать скорость в битах (Кбит/с, Мбит/с)»** и нажмите «Сохранить».

Настройка хранится на сервере qBittorrent, поэтому действует во всех браузерах.

## Что меняется

- Скорость в битах показывается везде: в строке состояния, в списке торрентов, в свойствах торрента, в заголовке вкладки.
- Лимиты скорости вводятся в Мбит/с, можно с дробной частью, например 0.5 или 12.5. Это касается всех окон с лимитами:
  - лимит для выбранных торрентов;
  - глобальные и альтернативные лимиты;
  - вкладка «Скорость» в настройках;
  - диалог добавления торрента.
- qBittorrent хранит лимиты с точностью до КиБ, поэтому введённое значение округляется до ближайшего КиБ. При следующем открытии оно читается тем же числом, с точностью до 0.01 Мбит/с.
- Используются десятичные единицы, как у провайдеров: 1 Мбит/с = 1 000 000 бит/с.
- Размеры и объёмы остаются в байтах.
- Когда флажок выключен, интерфейс ничем не отличается от стандартного.

Изменения лежат в [`patches/`](patches) и [`i18n/`](i18n). Остальное взято из исходников qBittorrent без изменений.

## Версии

Интерфейс qBittorrent привязан к версии самой программы, поэтому мод собирается под конкретную версию:

- `ghcr.io/dobriys/qbitmb-mod:latest` — под версию из `linuxserver/qbittorrent:latest`. GitHub Actions каждый день проверяет образ linuxserver и при выходе новой версии qBittorrent собирает мод заново.
- `ghcr.io/dobriys/qbitmb-mod:5.3.0` и т.п. — под конкретную версию. Нужен, если образ qBittorrent закреплён на определённой версии. Мод под другую версию можно собрать вручную: **Actions → Build mod → Run workflow**, указав версию.

При старте контейнера мод пишет в лог, под какую версию он собран и какая установлена:

```
**** qbitmb: WebUI from qBittorrent 5.3.0, installed qBittorrent 5.3.0 ****
```

Если в новой версии qBittorrent патч перестанет накладываться, сборка в Actions упадёт, а `latest` останется на предыдущей версии. В этом случае патч нужно обновить.

GitHub отключает запуск по расписанию в репозиториях без активности дольше 60 дней. Если это случится, включите workflow снова на вкладке Actions.

## Как вернуть стандартный интерфейс

Снимите галочку «Использовать альтернативный веб-интерфейс». Если интерфейс не открывается, остановите контейнер и поменяйте в `/config/qBittorrent/qBittorrent.conf`:

```
WebUI\AlternativeUIEnabled=false
```
